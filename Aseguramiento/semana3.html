TEMA 01
¿Qué son los Factores de Calidad?
📦
Concepto y Norma ISO/IEC 25010

"Los factores de calidad son características o atributos que determinan la capacidad de un producto de software para satisfacer necesidades explícitas e implícitas bajo condiciones especificadas."

— ISO/IEC 25010:2011 (SQuaRE): 8 características principales · 31 sub-características · Cada una con métricas · Base del estándar SQuaRE

📋
Los 6 Factores de la Semana
  • 1. Funcionalidad — ¿Hace lo que debe?
  • 2. Confiabilidad — ¿Lo hace de forma estable?
  • 3. Usabilidad — ¿Es fácil de usar?
  • 4. Eficiencia — ¿Es eficiente en recursos?
  • 5. Escalabilidad — ¿Puede crecer?
  • 6. Portabilidad — ¿Funciona en distintos entornos?
⚙️
Importancia Práctica
  • Guían decisiones de diseño
  • Base para testing y QA
  • Criterios de aceptación
  • Comunicación con el cliente

TEMA 02
Funcionalidad y Confiabilidad — La base del software de calidad
⚙️
Funcionalidad — Adecuación Funcional

"Grado en que el producto proporciona funciones que satisfacen necesidades declaradas e implícitas"

  • Completitud Funcional: El software cubre todas las tareas y objetivos que el usuario necesita realizar.
  • Corrección Funcional: Los resultados producidos son exactos, precisos y correctos según lo especificado.
  • Pertinencia Funcional: Las funciones facilitan el logro de tareas específicas sin incluir lo innecesario.

Ejemplo: Un sistema bancario debe transferir fondos correctamente (corrección) a todas las cuentas destino (completitud) sin ejecutar pasos irrelevantes (pertinencia).

🛡️
Confiabilidad — Reliability

La capacidad de mantener el rendimiento bajo condiciones establecidas.

  • 🛡️ Madurez: Frecuencia con que el sistema sufre fallos. Se mide con MTBF (Mean Time Between Failures).
  • ⚡ Disponibilidad: Proporción de tiempo en que el sistema está operativo. Sistemas críticos exigen 99.99% (el "4 nueves" de uptime).
  • 🔄 Tolerancia a Fallos: Capacidad de operar aun cuando ocurren fallas de hardware o software. Incluye degradación elegante del servicio.
  • 🔧 Recuperabilidad: Rapidez y completitud con que el sistema restaura su estado después de una interrupción. Se mide con MTTR.

Meta industria: MTBF > 720h · MTTR < 1h · Disponibilidad ≥ 99.9% · Tasa de fallos < 0.1%

TEMA 03
Usabilidad y Eficiencia de Desempeño
🖱️
Usabilidad — La experiencia del usuario como factor de calidad
  • 🎯 Reconocibilidad: El usuario reconoce si el software sirve para sus necesidades.
  • 📚 Aprendizaje: Facilidad con la que el usuario puede aprender a operar el sistema.
  • 🖱️ Operabilidad: Grado en que el software es fácil de operar y controlar.
  • 🛡️ Protección de errores: El sistema protege al usuario de cometer errores de operación.
  • 🎨 Estética UI: La interfaz facilita interacciones agradables y satisfactorias.
  • ♿ Accesibilidad: Personas con diferentes capacidades pueden usar el software igualmente.

Se mide con: SUS (System Usability Scale) · Pruebas de usuarios · Tiempo en tarea · Tasa de errores · NPS

⏱️
Eficiencia de Desempeño — Performance Efficiency

Usar los recursos mínimos para obtener el máximo rendimiento.

Sub-característica Meta Ejemplo
⏱️ Comportamiento Temporal < 200ms resp. APIs web Google: +100ms latencia = -1% ingresos
💾 Uso de Recursos < 70% CPU/RAM en pico Netflix: reducción 40% RAM con caché inteligente
📊 Capacidad Req. definidos por requisito Black Friday: 10x tráfico normal requiere planning

TEMA 04
Escalabilidad y Portabilidad
📈
Escalabilidad — Capacidad de crecer sin perder calidad
  • ⬆️ Escalabilidad Vertical (Scale Up): Aumentar los recursos de una sola máquina: más CPU, más RAM, discos más rápidos.
    ✅ Simple de implementar, sin cambios de arquitectura · ⚠️ Límite físico de hardware
  • ↔️ Escalabilidad Horizontal (Scale Out): Añadir más instancias/nodos al sistema distribuyendo la carga entre ellos.
    ✅ Sin límite teórico, alta disponibilidad · ⚠️ Mayor complejidad arquitectural

🚀 AWS, Azure y GCP ofrecen auto-scaling: el sistema escala automáticamente según la demanda, sin intervención humana.

🔀
Portabilidad — Transferibilidad entre entornos
  • 🔀 Adaptabilidad: Capacidad de adaptarse a entornos de hardware, software y uso diferentes sin acciones manuales adicionales.
  • 📥 Instalabilidad: Facilidad con que el software puede ser instalado o desinstalado en un entorno determinado sin errores.
  • 🔄 Reemplazabilidad: Capacidad de ser usado como sustituto de otro producto con el mismo propósito y en el mismo entorno.

Ejemplos: Java/JVM — mismo bytecode en cualquier SO · Docker — contenedores iguales en dev y producción · React Native — una app para iOS y Android

TEMA 05
Métricas, Tensiones y Caso Práctico
⚡
Tensiones Entre Factores de Calidad

No todos los factores pueden maximizarse simultáneamente — hay trade-offs inevitables.

Tensión Descripción
Funcionalidad ⚡ Usabilidad Más funciones = mayor complejidad de uso
Eficiencia ⚖️ Portabilidad Código optimizado es menos portable
Seguridad 🔒 Eficiencia Cifrado y validaciones consumen recursos extras
Escalabilidad 🌐 Confiabilidad Sistemas distribuidos son más difíciles de mantener estables

💡 La solución: priorizar según el contexto del negocio. Una app bancaria prioriza confiabilidad; una app social prioriza usabilidad.

🏫
Caso Práctico — Sistema de Gestión Académica
Factor Puntuación Observación
⚙️ Funcionalidad 85% Registra notas, asistencia y reportes. Falta módulo de comunicados.
🛡️ Confiabilidad 72% Caídas frecuentes en período de matrícula. MTBF < 48h durante picos.
🖱️ Usabilidad 61% SUS = 58/100. Docentes requieren 2+ horas de capacitación inicial.
⏱️ Eficiencia 70% Tiempo de respuesta: 4.2s promedio. Objetivo: < 2s. CPU al 89% en picos.
📈 Escalabilidad 55% Falla con > 200 usuarios simultáneos. Arquitectura monolítica sin escala horizontal.
📱 Portabilidad 80% Web app funciona en todos los navegadores. Sin app móvil nativa aún.
📏
¿Cómo Medimos Cada Factor?
  • Funcionalidad: Cobertura de requisitos · Tasa de defectos funcionales · % casos de uso implementados
  • Confiabilidad: MTBF · MTTR · Tasa de fallos · % uptime
  • Usabilidad: SUS Score (>68 = aceptable) · Tiempo en tarea · Tasa de errores · NPS
  • Eficiencia: Tiempo de respuesta (ms) · Throughput (req/s) · Uso CPU/RAM · Apdex Score
  • Escalabilidad: Usuarios concurrentes · Degradación bajo carga · Tiempo de escala horizontal
  • Portabilidad: Compatibilidad SO/navegadores · Tiempo de instalación · % código reutilizable

🛠️ Herramientas: JMeter · SonarQube · Lighthouse · Gatling · New Relic · Datadog · Selenium · SUS Questionnaire

Puntos clave de la semana
  • 📦 Factores ISO/IEC 25010 → Son atributos medibles que determinan la calidad real de un producto de software.
