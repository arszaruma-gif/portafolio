TEMA 01
¿Qué son los Patrones de Diseño?
🎯
Concepto — Gang of Four (GoF)

Introducidos por la Gang of Four (GoF), son soluciones estándar a problemas comunes en el diseño de software orientado a objetos.

  • 🔤 Lenguaje Común: Permiten a los desarrolladores comunicarse con términos técnicos claros (ej. "Usa un Adapter").
  • ♻️ Reutilización: Evitan reinventar la rueda ante problemas de diseño recurrentes.
📂
Categorías de la GoF
  • 🏗️ 1. Creacionales: Mecanismos de creación de objetos. (Esta semana)
  • 🔗 2. Estructurales: Composición de clases y objetos. (Esta semana)
  • 🔄 3. Comportamiento: Interacción y responsabilidades entre objetos. (Semana 7)

💡 "Los patrones no son fragmentos de código para copiar; son plantillas conceptuales para resolver problemas de diseño."

TEMA 02
Patrones Creacionales — Abstraen el proceso de instanciación de objetos
🏗️
El Catálogo Creacional Completo

📦 Singleton

Garantiza que una clase tenga una única instancia en todo el sistema y proporciona un punto de acceso global.

🏭 Factory Method

Define una interfaz para crear un objeto, pero deja que las subclases decidan qué clase exacta instanciar.

🏗️ Abstract Factory

Permite producir familias de objetos relacionados o dependientes sin especificar sus clases concretas.

🔨 Builder

Separa la construcción de un objeto complejo de su representación, permitiendo crear variaciones paso a paso.

📋 Prototype

Permite copiar u clonar objetos existentes sin que el código dependa de sus clases específicas.

💻
Patrón en Acción: Singleton — Conexión a Base de Datos

Problema: Múltiples instancias abiertas saturan los recursos del servidor.

Solución: Controlar el constructor internamente para garantizar una sola instancia.

class DatabaseConnection:
  _instance = None

  def __new__(cls):
    if cls._instance is None:
      cls._instance = super().__new__(cls)
      # Inicializar conexión aquí
    return cls._instance
📝
Mis apuntes

• Patrones Creacionales (Mecanismos de Creación de Objetos)
• Singleton: Asegura una única instancia global en toda la aplicación para no destruir el rendimiento del servidor. Ejemplo: Una conexión a Base de Datos o Gestor de Logs; en frameworks se ve en el EntityManager de Hibernate (Java) o servicios Singleton en .NET Core.
• Factory Method: Define una interfaz para crear un objeto, pero deja que las subclases decidan la clase exacta a instanciar. Ejemplo: Un sistema de Logística donde LogisticaTerrestre crea un Camion y LogisticaMaritima un Barco; en el mundo real se usa en LoggerFactory.getLogger() en Java.
• Abstract Factory: Permite producir familias de objetos relacionados sin especificar sus clases concretas. Ejemplo: Componentes de UI Multiplataforma donde una FabricaWindows crea botones/ventanas de Windows y una FabricaMac los de Mac para mantener la coherencia; usado en Look and Feel de Java Swing o kits de renderizado en Flutter.
• Builder: Separa la construcción de un objeto complejo de su representación para crearlo paso a paso de forma limpia, evitando constructores gigantes con argumentos null. Ejemplo: Un generador de peticiones HTTP complejas o consultas SQL, como el cliente moderno de Java: HttpClient.newBuilder().connectTimeout(...).build().
• Prototype: Permite copiar o clonar objetos existentes directamente en memoria sin depender de sus clases específicas ni realizar cargas costosas desde disco. Ejemplo: Un motor de videojuegos que genera 100 soldados enemigos idénticos clonando un soldado "Base" con un método .clonar(); implementado mediante .clone() en Java o Object.create() en JavaScript.

TEMA 03
Patrones Estructurales — Cómo se entrelazan los objetos para formar estructuras más grandes
🔗
El Catálogo Estructural (1/2)

🔌 Adapter

Permite que clases con interfaces incompatibles trabajen juntas, traduciendo las peticiones de una a otra.

🌉 Bridge

Separa una abstracción de su implementación, permitiendo que ambas varíen y crezcan de forma independiente.

🌳 Composite

Compone objetos en estructuras de árbol para representar jerarquías parte-todo, tratando objetos individuales y composiciones por igual.

📝
Mis apuntes

• Patrones Estructurales (Relación y Organización de Clases)
• Adapter (Adaptador): Permite que dos clases con interfaces incompatibles trabajen juntas traduciendo las peticiones de una a la otra. Ejemplo: Integrar un servicio externo que solo acepta XML en una app que procesa JSON; un adaptador traduce los datos de forma transparente sin reescribir la app. En el mundo real se usa en los drivers de bases de datos como JDBC.
• Bridge (Puente): Desacopla una abstracción de su implementación para que ambas evolucionen de forma independiente, evitando la explosión de clases. Ejemplo: Una app que exporta reportes (PDF, Excel) en varias plataformas (Web, Móvil); separa los "Tipos de Reporte" de los "Renderizadores de Plataforma". Usado en librerías gráficas para alternar entre DirectX u OpenGL por debajo.
• Composite (Objeto Compuesto): Organiza objetos en estructuras de árbol para representar jerarquías de parte-todo, tratando a objetos individuales y colecciones por igual. Ejemplo: El sistema de archivos donde un Archivo y una Carpeta implementan .obtenerTamano(); la carpeta calcula recursivamente el total de sus hijos bajo la misma interfaz uniforme. Se ve reflejado en el DOM de HTML o el árbol de componentes de React y Flutter.

🔗
El Catálogo Estructural (2/2)

✨ Decorator

Añade responsabilidades a un objeto de forma dinámica sin alterar su estructura interna ni usar herencia.

🏛️ Facade

Proporciona una interfaz simplificada y unificada para un subsistema complejo de clases, ocultando la complejidad técnica.

🪶 Flyweight

Optimiza el uso de memoria compartiendo eficientemente estados comunes entre grandes cantidades de objetos similares.

🔒 Proxy

Proporciona un sustituto o intermediario para controlar el acceso a otro objeto (ej. control de permisos, caché o carga perezosa).

📝
Mis apuntes

• Patrones Estructurales (Relación y Organización de Clases - Continuación)
• Decorator (Decorador): Añade responsabilidades a un objeto de forma dinámica en tiempo de ejecución sin alterar su estructura ni abusar de la herencia. Ejemplo: Un sistema de notificaciones donde envuelves un NotificadorCorreo básico dentro de un NotificadorSMS y un NotificadorWhatsApp para combinar alertas según el usuario. En el mundo real se ve en flujos de I/O de Java como new BufferedReader(new FileReader("...")).
• Facade (Fachada): Ofrece una interfaz simplificada y única frente a un grupo complejo de clases o un subsistema difícil de usar. Ejemplo: Un ConversorVideo que reduce a una sola línea como convertir("video.avi", "mp4") la compleja coordinación de codecs, audio y bitrates internos. Históricamente, la librería jQuery nació como una fachada para simplificar la caótica manipulación del DOM en los navegadores.
• Flyweight (Peso Ligero): Reduce drásticamente el uso de memoria RAM al compartir eficientemente datos idénticos entre miles de objetos similares. Ejemplo: Un procesador de texto donde el diseño y fuente de la letra "a" se almacena una sola vez en memoria, y cada letra en el documento solo guarda su posición X, Y. Se utiliza en el manejo de String Pools en lenguajes como Java o C# para apuntar variables idénticas al mismo texto.
• Proxy: Coloca un objeto intermediario para controlar el acceso al objeto real, permitiendo validar permisos, guardar en caché o retrasar cargas pesadas. Ejemplo: Un ProxyImagen para hacer Lazy Loading en una red social, mostrando un ícono ligero y descargando la foto real de alta resolución solo cuando se hace scroll. Utilizado en frameworks como Hibernate o Spring AOP para evitar consultas SQL hasta que el objeto sea requerido.

💻
Patrón en Acción: Adapter — Integración de APIs

Esencial cuando integramos servicios de terceros (Gateways de pago, APIs de mapas) que cambian con frecuencia sus firmas.

  • Problema: El API externo usa un método pay_usd(), pero nuestra arquitectura espera procesar_cobro().
  • Solución: El Adapter envuelve el API viejo y expone el formato nuevo.

Laboratorio Práctico — Refactorizar un Catálogo Académico
🎯
El Reto: Adapter XML → JSON

Dada una clase vieja que exporta listas de estudiantes en formato XML estructurado, los alumnos deberán implementar un Adapter para entregar la misma data en formato JSON plano.

Objetivo: No alterar la clase original que genera el XML.

Criterios de Evaluación:

  • ✅ Correcta separación de responsabilidades.
  • ✅ Uso de tipos nativos de Python para la conversión.
  • ✅ Pruebas que demuestren que el cliente interactúa únicamente con la interfaz del Adapter.
✅
Mi solución al laboratorio

Mi respuesta / código:

• Ejemplo de Código - Patrón Adapter en Python
• El Escenario: La APIExternaPago expone el método incompatible pay_usd(), pero nuestra arquitectura requiere obligatoriamente implementar el método estandarizado procesar_cobro() definido en ProcesadorPagoTarget.
• La Solución: El AdaptadorPago hereda del target esperado y envuelve la instancia de la API externa por composición, traduciendo de forma transparente la llamada del cliente hacia el método nativo.
• Implementación:
class APIExternaPago:
    def pay_usd(self, amount): print(f"Cobrando ${amount} USD usando la API Externa original.")
class ProcesadorPagoTarget:
    def procesar_cobro(self, monto): raise NotImplementedError()
class AdaptadorPago(ProcesadorPagoTarget):
    def __init__(self, api_externa: APIExternaPago): self.api_externa = api_externa
    def procesar_cobro(self, monto): self.api_externa.pay_usd(monto)
# Cliente: adaptador = AdaptadorPago(APIExternaPago()); adaptador.procesar_cobro(150)
