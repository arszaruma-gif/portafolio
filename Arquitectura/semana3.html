TEMA 01
La Fundación Estructural
🎯
Concepto Principal

Los estilos estructurales determinan la anatomía fundamental del software. Su objetivo central consiste en lograr organizar la complejidad mediante niveles de abstracción y límites de responsabilidad sumamente claros.

💡 Un estilo estructural no define el flujo dinámico de datos, sino los cimientos y fronteras del código fuente.

TEMA 02
Arquitectura en Capas (N-Tier)
🧱
Características e Impacto

Es el estilo clásico más extendido y utilizado. Organiza el sistema entero en un conjunto de grupos de responsabilidades horizontales.

  • Aislamiento: Las capas superiores dependen estrictamente de las inferiores, impidiendo el acoplamiento cruzado.
  • Seguridad: Cada una de las capas actúa de manera directa como una barrera de validación autónoma.
  • Mantenibilidad: Hace viable cambiar el Data Storage (ej. migrar de MySQL Master u otra DB) sin alterar la Interfaz de Usuario (UI).
⚠️
Análisis de Trade-offs

Riesgo de "Sinkhole Pattern": Ocurre cuando múltiples peticiones pasan a través de todas las capas del sistema sin realizar ninguna transformación ni lógica de negocio sustancial, consumiendo recursos de manera inútil.

📝
Mis apuntes

• Arquitectura en Capas (Layered Architecture)
• También conocida como arquitectura multicapa o Layered Architecture.
• Se basa en dividir una aplicación en diferentes niveles, donde cada capa cumple una función específica y se comunica únicamente con las capas adyacentes.

• ¿Qué es?
• La arquitectura en Capas organiza una aplicación separando sus responsabilidades en distintos niveles.
• Cada capa realiza una función específica y trabaja de manera independiente de las demás.
• Esta organización facilita el mantenimiento, las actualizaciones y el desarrollo de nuevas funcionalidades sin afectar al resto del sistema.

• Capas más Comunes
• Capa de Presentación: contiene la interfaz de usuario y permite la interacción con el sistema.
• Capa de Negocio: implementa la lógica de la aplicación y las reglas del negocio.
• Capa de Datos: administra el acceso, almacenamiento y recuperación de la información desde la base de datos.

• Características
• Divide la aplicación en capas con responsabilidades bien definidas.
• Cada capa se comunica únicamente con las capas cercanas.
• Facilita el mantenimiento y la organización del código.
• Permite reutilizar componentes en diferentes proyectos.
• Favorece la escalabilidad y la separación de responsabilidades.
• Es una de las arquitecturas más utilizadas en aplicaciones empresariales.

• Ventajas
• Código organizado y fácil de mantener.
• Facilita la detección y corrección de errores.
• Permite reutilizar componentes de negocio y acceso a datos.
• Hace más sencillo el trabajo colaborativo entre desarrolladores.

• Desventajas
• Puede generar una ligera pérdida de rendimiento debido al paso por varias capas.
• Si el sistema crece demasiado, algunas capas pueden volverse complejas.
• Un diseño inadecuado puede provocar dependencias innecesarias entre las capas.

• Ejemplos
• Sistema de banca en línea.
• Sistema de ventas o facturación.
• Sistema de gestión académica para universidades o colegios.
• Sistemas empresariales (ERP y CRM).
• Plataformas de comercio electrónico (E-commerce).

TEMA 03
Arquitectura de Microkernel (Plug-ins)
🔌
Sistemas Evolutivos

También conocida como Arquitectura de Plug-ins, está diseñada para proveer una flexibilidad extrema, separando por completo el núcleo de lo adicional.

  • Core System: Contiene únicamente la lógica mínima y esencial para que la aplicación funcione.
  • Plug-in Components: Componentes totalmente independientes que se acoplan al núcleo para añadir valor al negocio.
  • Escalabilidad: Resulta ideal para el diseño de aplicaciones de escritorio, navegadores web o editores extensibles.
⚠️
Análisis de Trade-offs

Complejidad Operativa: El despliegue de las aplicaciones se vuelve altamente complejo debido a la necesidad de gestionar y coordinar los cambios de versiones de múltiples plug-ins independientes.

📝
Mis apuntes

• Arquitectura de Microkernel (Microkernel)
• También conocida como arquitectura de núcleo mínimo.
• Se basa en separar las funciones esenciales del sistema de las funcionalidades adicionales mediante módulos o plugins.

• ¿Qué es?
• La arquitectura Microkernel mantiene un núcleo pequeño que contiene únicamente los servicios básicos del sistema.
• Las funcionalidades adicionales se implementan como plugins o módulos independientes.
• Esto permite ampliar el sistema sin modificar el núcleo principal, facilitando el mantenimiento y la evolución del software.

• Características
• Núcleo pequeño con funciones esenciales.
• Arquitectura modular y flexible.
• Fácil de extender mediante plugins.
• Permite agregar nuevas funcionalidades sin modificar el núcleo.
• Favorece el mantenimiento y la reutilización del código.
• Muy utilizada en aplicaciones que requieren complementos o extensiones.

• Ventajas
• Facilita la incorporación de nuevas funciones.
• Reduce el impacto de los cambios en el sistema principal.
• Mejora la escalabilidad y el mantenimiento.
• Permite desarrollar plugins de forma independiente.

• Desventajas
• Puede aumentar la complejidad de la comunicación entre el núcleo y los plugins.
• Un diseño inadecuado del núcleo puede afectar el rendimiento del sistema.
• Requiere una buena definición de interfaces entre los módulos.

• Ejemplos
• Eclipse IDE: permite instalar plugins para soportar distintos lenguajes de programación y herramientas.
• Visual Studio Code: amplía sus funcionalidades mediante extensiones desarrolladas por la comunidad.
• Mozilla Firefox: admite complementos para agregar nuevas características al navegador sin modificar su núcleo.

TEMA 04
Patrón de Pizarra (Blackboard)
🧠
Inteligencia Colectiva

Este estilo se basa en la colaboración de diversos componentes independientes sobre una base de datos común. Es de gran utilidad para problemas donde no existe una solución determinista paso a paso.

  • Pizarra (Blackboard): Memoria global donde reside el problema y donde se ejecutan los métodos de acceso y actualización.
  • Expertos (Knowledge Source): Módulos de conocimiento aislados que operan sobre la pizarra evaluando condiciones y ejecutando acciones.
  • Controlador (Control): Organismo que selecciona, configura y activa qué experto debe actuar en cada momento.
⚠️
Análisis de Trade-offs

Dificultad de Testing: Es extremadamente difícil de testear de forma automatizada debido al comportamiento intrínsecamente no determinista con el que interactúan los expertos sobre la pizarra.

📝
Mis apuntes

• Arquitectura de Pizarra (Blackboard)
• También conocida como arquitectura Blackboard o de Pizarra.
• Se basa en un espacio compartido donde diferentes componentes colaboran para resolver un problema de forma conjunta.

• ¿Qué es?
• La arquitectura de Pizarra utiliza una base de datos o memoria compartida llamada "Blackboard" donde los distintos módulos escriben y leen información.
• Cada componente aporta parte de la solución hasta resolver completamente el problema.
• Es especialmente útil para problemas complejos donde intervienen diferentes algoritmos o técnicas de procesamiento.

• Características
• Existe una base de datos compartida denominada Pizarra (Blackboard).
• Varios módulos trabajan de manera simultánea sobre la misma información.
• Cada módulo aporta una parte de la solución del problema.
• La información se actualiza continuamente conforme avanzan los procesos.
• Favorece la colaboración entre diferentes componentes especializados.
• Es ampliamente utilizada en sistemas de Inteligencia Artificial y procesamiento de información.

• Ventajas
• Facilita la colaboración entre múltiples módulos especializados.
• Permite resolver problemas complejos mediante el trabajo conjunto de diferentes algoritmos.
• Es flexible y fácil de ampliar incorporando nuevos componentes.
• Favorece la reutilización de módulos independientes.

• Desventajas
• Puede presentar problemas de rendimiento cuando muchos módulos acceden simultáneamente a la pizarra.
• La coordinación entre componentes puede aumentar la complejidad del sistema.
• Requiere un mecanismo eficiente para controlar el acceso a la información compartida.

• Ejemplos
• Sistemas de reconocimiento de voz.
• Sistemas de diagnóstico médico basados en Inteligencia Artificial.
• Sistemas de reconocimiento y procesamiento de imágenes.
• Sistemas expertos para la toma de decisiones.

LABORATORIO
Laboratorio Práctico de la Semana
✅
Reto Desarrollado — Sistema Extensible (Microkernel)

Enunciado de la práctica: Desarrollar en Python la estructura de un núcleo modular (Core) que acepte el registro dinámico de nuevos componentes ("Plug-ins") de notificación externa independientes sin alterar el núcleo central.

Estructura del Código implementado:

class Core:
    def __init__(self):
        self.p = []  # Almacén de plug-ins registrados dinámicamente

    def add(self, x):
        self.p.append(x)  # Registrar nuevo plug-in

    def notify(self, m):
        for s in self.p:
            s.send(m)  # Ejecutar envío en cada módulo

Puntos Clave de la Semana
💡
Puntos clave
  • 🧩 Los estilos estructurales moldean los límites de capas y responsabilidades lógicas del sistema.
  • 🌊 Las arquitecturas en capas se exponen de forma común al fenómeno adverso del Sinkhole Pattern.
  • 🔌 El estilo Microkernel potencia de gran manera las aplicaciones evolutivas mediante componentes independientes.
  • 🎲 El patrón de Pizarra se desmarca al trabajar sobre escenarios complejos de naturaleza no determinista.
